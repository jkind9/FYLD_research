# Task 03: Define observation and pose contracts with known geometry

## In plain English

Make the meaning of every distance and camera position explicit. Test simple shapes and camera movements with known answers. The same saved inputs should work with different estimators and reconstruction methods.

## What

Define the minimal saved observation and pose schemas in experiment READMEs and implement known-geometry tests/adapters within the owning experiment. Agree transform direction, depth definition, timestamp associations and segment identifiers before real estimation.

This is the first implementation task under the 2 October decision. Task 04 follows as the supplied-input reconstruction control. Task 09 reuses the same frames/units for object association; task 08 checks phone capture independently alongside this work.

## Why

A correct-looking surface can hide wrong depth units, reversed transforms or reset origins. Known geometry provides a control that does not depend on another unfinished component.

Task 02 completed acquisition on 2026-10-02. Its receipts identify 881 raw RGB/depth pairs, 880 exact-ID posed pairs (IDs 1..880; raw image 0 has no supplied pose), and a separate reference point cloud. data/icl_nuim/conventions.json records negative fy, axial PNG depth, camera-to-world pose direction and the reflection-containing SurfReg surface transform. These are documented inputs for this task to test independently; both extraction receipts deliberately leave scoring_ready false. No positional row-shift, TUM intrinsics substitution or identity world-to-surface mapping is valid by default.

1. Specify camera-axis metres versus viewing-ray range, valid masks, intrinsics for actual resolution and capture-clock units.
2. Specify T_world_camera, optical axes, quaternion order and world-frame/segment identity. Record adapter conventions per dataset.
3. Write independent tests before adapters:known translation and rotation, invalid depth, timestamp boundary, and distinct segment origins.
4. Verify projection/backprojection round trips and the evaluator's frame relation to the ICL reference mesh.
5. Reject cross-segment use without an established transform. Keep fixtures independently specified rather than generated by the implementation being scored.

## Invariants and recovery

Reference inputs remain unchanged and outside estimated-method inputs. Record units, frame identities and provenance at each boundary. A partial download or run is not ready data. Publish completed records only after required artifacts validate; interrupted work remains identifiable. Separate origins cannot be fused without a documented transform. No phone, cloud service or GPU is required for the initial control.
