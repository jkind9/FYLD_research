# Shared implementation

The canonical [walkthrough runner](walkthrough/README.md) calls six ordered layers: capture, depth, camera position, surface, site measurements and object counting. Each has a swappable method choice with a contract in `walkthrough/steps/contracts.py`. Recorded depth and poses can be supplied as labelled reference controls to test later layers. [Task59](../task_list/open/59_make_walkthrough_layers_swappable.md) records this refactor; [Task58](../task_list/closed/58_organise_six_step_walkthrough_orchestration.md) records the original organisation.

Reference inputs match each frame to its nearest recording within the selected tolerance, allowing nearby frames to reuse a reference. They consume decoded images one at a time. Missing methods report why they are unavailable before loading timing starts.

Each method remains independently usable within its [experiment](../experiments/README.md). Error analysis is imported through each experiment's dedicated validation area after predictions are saved. Reusable records, mathematics and run exports remain in [experiments/shared](../experiments/shared/README.md). The root runner coordinates these pieces. It does not duplicate them.

The local TUM input copies RGB only for methods. Its supplied depth and poses stay out of ordinary methods; explicit reference controls may supply them for isolated-layer checks. The TUM tracking reference source and hash are recorded even while tracking is unavailable; the optional reference file is hashed before its scoring loader runs. Layer checks compare output frame IDs with their upstream inputs. Real depth and site measurements remain explicitly unavailable until Tasks54/55 supply them. A failed or partial run retains all six statuses and cannot publish complete predictions. The independently measured complete walkthrough remains Task56 work. Earlier five-layer diagrams group reconstruction and mapping together; the runner executes them separately.

Each run includes an offline `output/visualizations/index.html` and `manifest.json` for the six stages. Visuals name the producing method and source. Depth masks show valid-pixel counts and a colour overlay on the source image. Object overlays show the proposal count; software-control boxes are marked synthetic. Full coloured point clouds are exported as PLY; their PNG overview is a labelled display sample. These exports help inspect each run and do not replace numeric predictions or validation.

The earlier package is preserved in [the Task 00 archive](../archive/task00_prototype/README.md). It is evidence and potential source material, not a validated foundation for the new experiments.
